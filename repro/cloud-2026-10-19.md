## README gaps (none of them changed a result)

1. **The engine needs Python 3.11+, and this README doesn't say so.** This README says "Python 3.8+" for the
   verifier, right above "Going further". The engine's own README says 3.11+. A stranger on 3.8–3.10 would pass the
   verifier and could then fail on the engine.
2. **pytest is not stdlib, and this README doesn't say to install it.** "All 170 tests pass" comes without an install
   step or a test command. The engine README does give `pip install pytest && python -m pytest`. On Ubuntu 24.04 the
   system pip is externally managed (PEP 668), so I used a venv to install pytest. I did not try the bare
   `pip install` here.
3. **The test suite takes about 15 minutes.** It took 917 s here. This README doesn't mention that, though the engine
   README does ("~15 min"). Someone expecting a quick check may think the run has hung.
4. **`regrade_frozen_bar.py` takes about 47 s and prints only to stdout.** The README doesn't say how long it takes,
   or that you must redirect stdout to a file before diffing. The "re-encoded UTF-8" note shows that a Windows
   redirect may not be byte-identical, but the README gives no comparison command. On Linux, `cmp` against the raw
   stdout was byte-identical with no re-encoding.
5. **The README commands use `python`.** On a stock Ubuntu with no `python-is-python3` package, only `python3`
   exists. On this VM `python` happened to work.
6. **`reproduce.py` writes a run directory into the clone** (`runs/<timestamp>_cache_eviction_deterministic`). It is
   gitignored, so `git status` stays clean, but the README doesn't mention it.
